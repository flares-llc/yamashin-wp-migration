# Yamashin WP Migration v1.0.0

2つのWordPress環境間で、方向を明示した差分移行を行う最初の完成版です。`push`と`pull`はリリース作成時に固定され、自動双方向同期は行いません。

## 主な機能

- 投稿、固定ページ、CPT、分類、メタ、コメント、添付、Uploadsを可搬UIDで移行
- ユーザー、許可済みオプション、登録済み独自テーブルを安全規則に従って移行
- テーマ、プラグイン、mu-plugin、同一バージョンのWordPress本体を内容ハッシュで比較・転送
- Merkleマニフェストとverified receiptを使った三方向差分
- ドライラン、項目単位の競合解決、三重確認式の削除、`plan_hash`拘束
- 適用前スナップショット、自動ロールバック、保持期間中の手動ロールバック
- 再開可能なチャンク転送と100項目単位の適用job
- HMAC署名REST API、Streamable HTTP MCP、GitHub Release配布のstdioブリッジ

## 要件

- WordPress 6.0以上。移行元と移行先は同じWordPress版
- PHP 8.0以上
- MySQL 5.7以上またはMariaDB 10.4以上を推奨
- OpenSSL、JSON、hash拡張
- 書き込み可能な`wp-content`と、変更対象以上の退避容量

## 検証

- PHP 8.0構文、363件の単体・静的アサーション
- staging／production各61項目の実HTTP認証・設定回帰
- 初回・更新・競合・明示削除・push／pull・再送・中止・自動／手動ロールバック
- 10,036項目のコンテンツ移行、約87MB相当のサイト全体manifest
- OpenAPI 3.1、全JSON Schema、MCP SDK／Inspector、npm audit
- 配布ZIPのクリーン有効化、v0.1.0からの非破壊アップグレード、アンインストール

## 対応外

WordPress Multisite、WordPress版更新、URL・秘密情報を含む完全クローン、SSH、GCS／Google Drive保存は対象外です。`siteurl`、`home`、`wp-config.php`、暗号鍵、認証・ライセンス情報、セッション、Yamashin WP Migration自身の接続状態は移行先の値を保持します。

一般のIssue、Discussion、機能要望、外部Pull Requestは受け付けていません。脆弱性はGitHubの非公開窓口へ報告してください。
